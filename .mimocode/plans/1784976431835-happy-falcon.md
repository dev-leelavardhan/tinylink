# Email Verification - Gap Analysis & Improvement Plan

## Executive Summary

The existing email verification implementation covers core functionality well but has gaps in API design alignment, audit logging, rate limiting granularity, and email fallback support.

---

## Current Implementation Analysis

### What's Already Implemented (Strong)

| Feature | Status | Notes |
|---------|--------|-------|
| OTP Generation | ✅ | Using `crypto.randomInt()` (cryptographically secure) |
| OTP Hashing | ✅ | SHA-256 with salt (guide prefers Argon2, but acceptable) |
| OTP Length | ✅ | 6 digits |
| OTP Expiry | ✅ | 10 minutes (600 seconds) |
| Redis + DB Storage | ✅ | Dual storage with Redis fast path |
| Rate Limiting | ⚠️ | Per-user only, missing IP-based |
| Attempts Limit | ✅ | Max 5 attempts |
| Resend Cooldown | ✅ | 60 seconds |
| OTP Invalidation | ✅ | Previous OTPs invalidated on resend |
| Account Activation | ✅ | Updates status to ACTIVE |
| Generic Responses | ✅ | For resend verification |
| HTML Email Templates | ✅ | With OTP and expiry info |
| SMTP Configuration | ✅ | Nodemailer with env vars |

## Critical Gaps

### 1. API Design Mismatch (HIGH PRIORITY)

**Guide requires:**
```json
POST /auth/verify-email
{ "email": "user@example.com", "otp": "482931" }
```

**Current implementation:**
```json
POST /auth/verify-email
{ "userId": "clxxx...", "otp": "482931" }
```

**Impact:** Client must know user ID to verify email, which defeats the purpose of email-based verification.

**Files to modify:**
- `src/users/dto/verify-email.dto.ts`
- `src/users/use-cases/user-verify-email.service.ts`
- `src/users/controllers/auth.controller.ts`

---

### 2. Missing Audit Logging (HIGH PRIORITY)

**Guide requires logging:**
- OTP generated
- OTP resent
- OTP verified
- OTP expired
- OTP failed
- Too many attempts
- Too many resend requests

**Current:** Basic info/warn logging, no structured audit trail.

**Missing fields:** IP address, user agent, timestamp precision.

**Files to create/modify:**
- New: `src/audit/audit.service.ts`
- New: `src/audit/audit-log.prisma` (or add to existing)
- Modify: All OTP-related services

---

### 3. IP-Based Rate Limiting (MEDIUM PRIORITY)

**Guide requires:**
- Verify Email: 5 requests / 10 minutes / IP
- Resend Verification: 3 emails / hour / account
- Global: 20 verification requests / hour / IP

**Current:** Only per-user rate limiting via Redis.

**Files to modify:**
- `src/users/use-cases/user-otp.service.ts`
- `src/users/controllers/auth.controller.ts`

---

### 4. Verification Token Schema Enhancement (MEDIUM PRIORITY)

**Guide specifies:**
```prisma
model VerificationOtp {
  id          String   @id
  userId      String
  type        String   // EMAIL_VERIFICATION
  otpHash     String
  expiresAt   DateTime
  createdAt   DateTime
  usedAt      DateTime?  // vs boolean
  attempts    Int      @default(0)
  resendCount Int      @default(0)
}
```

**Current schema:**
```prisma
model VerificationOtp {
  id        String   @id
  userId    String
  email     String
  otpHash   String
  salt      String
  expiresAt DateTime
  used      Boolean  // not usedAt timestamp
  createdAt DateTime
  // missing: type, attempts, resendCount
}
```

**Files to modify:**
- `prisma/schema.prisma`
- Migration file
- Repository methods

---

### 5. Plain-Text Email Fallback (MEDIUM PRIORITY)

**Guide requires:** HTML + plain-text fallback for email clients.

**Current:** Only HTML emails.

**Files to modify:**
- `src/mailer/types.ts` - Add `text` field
- `src/mailer/mailer.service.ts` - Send both
- `src/users/use-cases/user-register.service.ts`
- `src/users/use-cases/user-resend-verification.service.ts`

---

### 6. SMTP Resilience (LOW PRIORITY)

**Guide requires:**
- Connection timeout
- Retry on temporary failures
- Configurable sender name

**Current:** No timeout, no retry, no sender name config.

**Files to modify:**
- `src/mailer/mailer.service.ts`

## Implementation Plan

### Phase 1: API Alignment (Critical)
1. Change `verify-email` endpoint to accept `email` instead of `userId`
2. Update DTO validation
3. Modify service to look up user by email

### Phase 2: Audit Logging
1. Create audit log schema/model
2. Implement audit service
3. Add logging calls to all OTP operations

### Phase 3: Enhanced Rate Limiting
1. Add IP extraction middleware
2. Implement IP-based rate limits
3. Add global rate limiting

### Phase 4: Schema Enhancement
1. Add `type`, `usedAt`, `attempts`, `resendCount` fields
2. Create migration
3. Update repository methods

### Phase 5: Email Improvements
1. Add plain-text email templates
2. Add SMTP timeout/retry
3. Add sender name config
