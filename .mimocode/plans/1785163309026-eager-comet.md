# Plan: Refresh Token Production-Grade Improvements

## Overview

Six targeted fixes to align the refresh flow with the spec guide. Each is independent and can be applied in sequence.

## 1. Distinct error responses for expired/revoked/missing cookie

**Problem:** All refresh failures collapse into `"Invalid refresh token"`. The guide specifies distinct messages.

**Files:**
- `server/src/users/constants/user.constants.ts` — add new error messages
- `server/src/users/repositories/session.repository.ts` — add `findSessionContextForRefresh()` that returns session state instead of just `null`
- `server/src/users/use-cases/user-login.service.ts` — branch on session state to throw distinct errors
- `server/src/users/controllers/auth.controller.ts` — fix missing cookie to throw `UnauthorizedException` instead of generic `Error`

**Changes:**

1. Add to `USER_ERROR_MESSAGES`:
   - `MISSING_REFRESH_TOKEN: 'Authentication required.'`
   - `SESSION_EXPIRED: 'Session expired.'`
   - `SESSION_REVOKED: 'Session revoked.'`

2. Add `SessionRefreshContext` type and `findSessionContextForRefresh()` to `session.repository.ts`:
   ```ts
   type SessionRefreshContext =
     | { status: 'active'; session: Session }
     | { status: 'expired'; session: Session }
     | { status: 'revoked'; session: Session }
     | { status: 'not_found' };
   ```
   Query by `refreshTokenHash` without the `revokedAt`/`expiresAt` filters, then classify the result.

3. In `user-login.service.ts` `refresh()`: replace `findByRefreshTokenHash` with `findSessionContextForRefresh`, then switch on `context.status` to throw the correct error.

4. In `auth.controller.ts` line 92-94: replace `throw new Error(...)` with `throw new UnauthorizedException(USER_ERROR_MESSAGES.MISSING_REFRESH_TOKEN)`.

## 3. Fix `rotateSession` return type

**Problem:** `$transaction([...])` returns an array, but the method signature says `Promise<Session>`. The `as unknown as Promise<Session>` cast hides the array.

**File:** `server/src/users/repositories/session.repository.ts`

**Change:**
```ts
async rotateSession(
  oldSessionId: string,
  newSessionData: Prisma.SessionCreateInput,
): Promise<Session> {
  const [, newSession] = await this.prisma.$transaction([
    this.prisma.session.update({
      where: { id: oldSessionId },
      data: { revokedAt: new Date() },
    }),
    this.prisma.session.create({ data: newSessionData }),
  ]);
  return newSession;
}
```

Also update caller in `user-login.service.ts` — no change needed since it already uses the result as a single session.

## 4. Add sliding session expiry option

**Problem:** Sessions always expire at original time. The guide describes an opt-in sliding window.

**Files:**
- `server/src/users/constants/user.constants.ts` — add `SLIDING_SESSION_ENABLED: false`
- `server/src/users/use-cases/user-login.service.ts` — conditionally extend `expiresAt`

**Change:** In `refresh()`, when sliding is enabled, set `expiresAt = daysFromNow(SESSION_EXPIRY_DAYS)` (from now). When disabled, copy `expiresAt` from the old session. Currently it always creates a new session with fresh expiry — the sliding flag just controls whether the old session's expiry is preserved or extended.

Since the current behavior already creates a new session with `daysFromNow(7)` (effectively sliding), the flag provides a way to disable this and keep the original expiry window.

## 5. Explicit `lastUsedAt` tracking on session

**Problem:** The guide says to update `lastUsedAt = now()` on refresh. Currently a new session is created, so `lastUsedAt` defaults to `createdAt`. This is fine for rotation, but let's make it explicit in the new session data.

**File:** `server/src/users/use-cases/user-login.service.ts`

**Change:** Add `lastUsedAt: new Date()` to the `newSessionData` passed to `rotateSession()`. This makes the intent explicit and ensures the field is set even if the Prisma default changes.
